## Deliverables and acceptance
1. llm/redact.py + extract.redact(): Indian PII before any model call: phone (+91, 10-digit, spaced), Aadhaar (12 digits with or without spaces), PAN, email, UPI id, bank account-like long digits. Replace with typed placeholders, return count. Tests with at least 25 positive and 15 negative cases (PIN codes, dates and hour ranges must NOT be redacted). Document the limit: names are not detected (no NER); say so in the module docstring.
2. extract_roles(brief_text, language_hint): redact first; system prompt with the 24-skill taxonomy (import taxonomy.SKILLS) and 4-6 few-shot examples (Hindi, English, Hinglish); output validated against ExtractionResult; skills outside the taxonomy are dropped and noted; low-confidence roles are listed in needs_decision; counts default sensibly from team size or crowd size and are marked medium confidence; tolerant of Devanagari numerals. max_tokens 3000. Never crash the API: on LLM failure raise llm.client.LLMError (head maps it to 502).
3. backend/eval/extraction/: 30 labelled briefs (12 Hindi, 10 English, 8 Hinglish/Awadhi-flavoured) with ground-truth roles and skills (JSON file), a runner (python -m eval.extraction.run) that calls extract_roles live, and metrics: role recall and precision on taxonomy skills, count accuracy within +-1, abstention rate, per-language breakdown. docs/lanes/B-llm-evidence/EXTRACTION_EVAL.md with the command and its REAL pasted output including the failures. Do not tune the briefs to the model after seeing results; if you fix a prompt, say so and rerun.
4. draft_cards(task, host_notes, attendance_rows, assignments): LLM drafts ContributionCards from host notes (one per volunteer mentioned or assigned), fills recorded_hours from attendance_rows (rows have volunteer_id, task_id, hours, check_in, check_out, optional age, guardian_consent), status always draft, drafted_by ai; deterministic fallback parser if the LLM fails. Never marks anything confirmed.
5. evidence/rules.py check_card: at least 9 deterministic rules, each with tests: hours_exceed_recorded, no_attendance_record, implausible_hours (>12 per day), duplicate_evidence_ref, identical_summary_text (copy-paste claims), overlapping_tasks (same volunteer, overlapping hours on different tasks), minor_without_guardian_consent, self_declared_skill_unconfirmed, round_number_inflation (suspicious clustering), and one more of your choice with justification. Flags carry code, severity, plain-English message. Nothing is ever auto-rejected.
6. evidence/ledger.py Ledger: append-only hash chain (sha256 over prev_hash, ts, action, card_id, actor, payload_hash), persisted to a JSON-lines file (path or temp), verify() detects any edited, deleted or reordered entry and reports first_bad_index; thread-safe append. Tests include a tamper test. Docstring states: a hash chain shows edits, not truth.
7. evidence/badges.py to_credential: first read docs/research/R3-credentials-privacy.md. If R3 verified the Open Badges 3.0 / W3C VC fields from the primary spec, emit a compatible UNSIGNED credential (OpenBadgeCredential type, issuer, credentialSubject with achievement, evidence, validFrom) and say clearly it is unsigned and not issued by any authority; otherwise a minimal documented JSON labelled OB3-style, unsigned. Tests validate required keys. Only confirmed/corrected cards may be exported (API enforces).
