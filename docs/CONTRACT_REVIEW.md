# Contract review — Pass 1

Scope: contract, lane cards, backend stubs, and current frontend skeleton only. No code changed.
Severity: P0 = blocks an honest demo/evaluation; P1 = likely integration or correctness failure; P2 = important but containable.

## 1. Defects

- **P0 — API contradicts the required comparison.** `TRD.md:28-29,52` and `docs/lanes/A-solver/TASK.md:9,12` require four methods, but `backend/app/main.py:96-99,101-107` returns only `cp_sat` and `nearest_skill`; solver interface exposes the other baselines at `backend/app/solver/api.py:18-24`. **Fix:** return a `dict[Method, RosterResult]` (all four) from `/api/roster`, or make that endpoint explicitly two-method and provide a separate all-method comparison endpoint used by the UI.
- **P0 — Partial role fulfillment cannot be reported.** `backend/app/schemas.py:64,121-130,153-159` models assignment slots but only `unfilled_role_ids`; a role with count 3 and 2 filled has no representation of which slot is open. **Fix:** add `unfilled_slots: list[RoleSlotRef]` (`role_id`, zero-based `slot_index`) and require unique `(role_id, slot_index)` assignments; keep role IDs only as a derived summary.
- **P0 — Evidence payloads bypass the shared contract.** `backend/app/main.py:134-145` accepts bare `list[dict]` for attendance and assignments; Lane B requires attendance fields at `docs/lanes/B-llm-evidence/TASK.md:10`, while Lane A emits `Assignment` objects at `backend/app/schemas.py:121-130`. **Fix:** define `AttendanceRow` and accept `list[Assignment]` (or a typed `RosterResult`) so validation, field names, and OpenAPI agree.
- **P1 — Evaluation contract tests freeze endpoints at 501.** `backend/tests/test_contract.py:34-36` asserts 501 for `/api/volunteers`, `/api/tasks`, `/api/ledger`, `/api/ledger/verify`, and `/api/eval`, although `backend/app/main.py:71-78,194-202,219-222` implements them and TRD requires them. **Fix:** replace placeholder assertions with response-shape and behavior tests before accepting lanes; retain 501 checks only for deliberately unimplemented routes.
- **P1 — LLM failure mapping is absent.** `TRD.md:36,46` promises 502/manual entry on LLM failure; `backend/app/main.py:22-26,86-89` catches only `NotImplementedError`. **Fix:** catch `LLMError` at extraction/draft boundaries, return a stable 502 error code and manual-entry hint; keep validation failures as 4xx.
- **P1 — Extracted roles do not carry `RoleSpec.id`.** `ExtractedRole` at `backend/app/schemas.py:91-98` has no ID, while `RoleSpec` requires one at `61-70`; `to_role_specs()` has no ID policy (`backend/app/llm/extract.py:17-18`). **Fix:** prescribe deterministic request-local IDs (`role-1`, …) during conversion and preserve them when the organiser edits/submits the task.
- **P1 — Required-field and domain validation is incomplete.** `RoleSpec.required_skills` at `backend/app/schemas.py:65` and `ExtractedRole.required_skills` at `93-95` accept unknown IDs; `TaskSpec.team_size` at `83-86` is not reconciled with role counts; volunteer latitude/longitude and counters are unconstrained (`18-35`). **Fix:** validate skills against `SKILLS`, coordinates/ranges and nonnegative counters, and reject or explicitly flag task-size/count mismatch.
- **P1 — Solver objective priority is not enforceable as written.** `TRD.md:39` calls the objective “lexicographic-style weighted” but sets no bound proving lower-priority terms cannot outweigh must-role coverage. **Fix:** use sequential solves by objective tier, or document integer weights with proven upper bounds and test a case where all secondary preferences conflict with one must slot.
- **P1 — Ledger claim exceeds hash-chain guarantees.** `TRD.md:49` and `docs/lanes/B-llm-evidence/TASK.md:12` claim detection of any deleted entry; a plain chain cannot detect truncation of its tail without a separately trusted head/checkpoint. **Fix:** state the threat model; persist/anchor the latest hash outside the file (or narrow the claim to edits/reordering/interior deletion relative to a trusted head).
- **P1 — API has no state recovery or idempotency contract.** Cards/attendance live only in globals (`backend/app/main.py:29-37,145-151`), while the ledger is file-backed (`54-57`); restart or multiple workers can make cards disagree with the ledger, and retrying draft duplicates cards. **Fix:** for prototype, persist cards and attendance beside the ledger and reload on startup; make draft requests idempotent using a request/task key and define duplicate behavior.
- **P1 — Host decisions are unchecked transitions.** `backend/app/main.py:161-175` permits any actor string to confirm/reject repeatedly, and correction changes only claimed hours; schema allows negative hours (`backend/app/schemas.py:193-205`). **Fix:** constrain hours to nonnegative values, require correction payload fields, define allowed state transitions and actor semantics; label the unauthenticated host flow as a local demo only.
- **P1 — CORS contradicts the security requirement.** `TRD.md:58` says local-development origins only; `backend/app/main.py:19` allows every origin. **Fix:** read an explicit local allowlist from configuration, with a localhost-only development default.

## 2. Cross-lane and frontend ambiguities — resolve before implementation

- **Attendance shape and hours:** Lane B says rows have `volunteer_id`, `task_id`, `hours`, `check_in`, `check_out` (`docs/lanes/B-llm-evidence/TASK.md:10`), but does not say whether `hours` is claimed or attendance-derived. Standardize `AttendanceRow{volunteer_id, task_id, check_in, check_out, recorded_hours, age?, guardian_consent?}`; require ISO-8601 timestamps with offset, derive recorded hours from the interval, and never infer claimed hours from attendance.
- **Assignments passed to draft:** use the exact selected roster’s `assignments: Assignment[]` (`role_id`, per-role zero-based `slot_index`, `volunteer_id`, `volunteer_name`, …), not arbitrary dictionaries or a reconstructed frontend shape. Specify that cards are drafted for the union of assigned volunteers and volunteers explicitly mentioned in notes; no duplicate card per volunteer/task/role.
- **Slot semantics:** `TaskSpec.slot` is a free string (`backend/app/schemas.py:73-86`), while volunteers use free-string `available_slots` (`18-35`) and taxonomy has a finite `SLOTS` list (`backend/app/taxonomy.py:30`). Make both IDs from `SLOTS`; define them as local day-of-week/day-part for prototype availability only. For attendance overlap and real dates, use offset timestamps, not `slot`.
- **Must/should, any-of, and coverage:** `RoleSpec.priority` allows `should` (`backend/app/schemas.py:67`), `required_skills` says any-of (`65`), but coverage language alternates between all required slots and must slots (`TRD.md:39-40`). Define must slots as the coverage denominator and hard objective tier; should slots are optional secondary coverage; one or more listed skills at `min_level` qualifies, and an empty skill list has an explicit open-to-all meaning.
- **IDs and generated role conversion:** all IDs are unconstrained strings (`backend/app/schemas.py:18-19,61-63,73-75,193-196`). Standardize stable synthetic IDs (`v-001`, `task-01`, `role-01`) and conversion IDs (`role-01`); card IDs must be unique and stable for a draft retry. Reject references to unknown IDs at API boundaries.
- **Single source of demo data:** `/api/roster` accepts a task but always uses cached synthetic volunteers (`backend/app/main.py:101-107`); frontend has no API client yet (`frontend/src/App.tsx:1-122` is Vite starter). Specify whether the UI selects a generated task or submits an extracted/editable `TaskSpec`, and how the exact roster is retained for dropout, why-not, and evidence draft calls.
- **Offline/cache behavior:** PRD calls for offline cached outputs (`PRD.md:44`), TRD says record/replay (`TRD.md:45`), but no UI/API contract says how to select replay mode or what happens on cache miss. Make replay mode the demo default, expose cache-miss as a visible manual path, and never silently call live mode.

## 3. Metric definitions and anti-gaming fixes

TRD §5 (`TRD.md:39-42`) and Lane A (`docs/lanes/A-solver/TASK.md:8-13`) need these tightened before reporting:

- **Role coverage:** use `filled qualified must-slots / total must-slots`; report should-slot coverage separately. Count each `(role_id, slot_index)` once, enforce all hard eligibility rules, and report infeasible tasks/misses. Do not average per-role percentages (small roles would dominate) or count unqualified assignments.
- **Robustness:** enumerate each assigned volunteer’s single-dropout scenario; after removing that volunteer, find a maximum matching from remaining assigned volunteers plus standby to every must slot, with each person used at most once per scenario and qualification, availability, travel, consent and forced constraints rechecked. Score scenarios passing / assigned-volunteer scenarios; report zero when no assignments and `N/A` when there are no must slots. Standby must be a unique eligible pool, not an unlimited per-role copy. State separately whether dropping a standby is out of scope.
- **Repeat-pick share:** define as assigned volunteers with `times_picked_last_90d >= 3 / assigned volunteers`, with `N/A` for empty rosters. It is only a descriptive repeat-exposure measure, not fairness by itself; compare methods on identical task/pool inputs and publish coverage beside it so a method cannot “improve” by leaving roles empty.
- **Exposure Gini:** current schema says Gini among assigned (`backend/app/schemas.py:144-145`), which lets a planner look fair by choosing only newcomers and ignores excluded eligible people. Compute Gini over the same task-eligible candidate pool’s pre-event `times_picked_last_90d` plus the simulated current pick for selected people; publish eligible-pool definition and report coverage. Define Gini=0 for all-zero exposure and `N/A` for empty eligible pools.
- **Baseline parity and uncertainty:** Lane A’s property requirement `cp_sat role_coverage >= nearest_skill` (`docs/lanes/A-solver/TASK.md:13`) is not a general guarantee under a time-limited feasible CP-SAT solve. Compare identical hard constraints and inputs; call nearest-skill the nearest *eligible, qualified* candidate; report any method’s infeasibility. For random-feasible, average multiple declared seeds. Bootstrap paired task IDs (same resampled tasks for every method), not independent method rows; with n=10 call intervals descriptive and include paired deltas, raw task results and misses.

## 4. Demo risks and cheapest mitigation

- **Frontend is still the Vite counter template** (`frontend/src/App.tsx:7-122`); PRD expects a live comparison, edit/approve, dropout, evidence and ledger flow. **Mitigation:** cut scope to one rehearsed happy path with explicit synthetic-data label and pre-populated task.
- **Startup path is not contracted:** ADR says FastAPI serves built UI (`ADR.md:65-68`), but no static mount appears in `backend/app/main.py:1-222`. **Mitigation:** add/verify one launcher that starts API and serves the production build; keep a local browser URL ready.
- **LLM can be slow or unavailable:** observed ~11 s and live gateway dependency (`ADR.md:25-33`, `TRD.md:45`). **Mitigation:** warm a known replay cache before stage, pin replay mode, rehearse a cache-miss fallback.
- **State can vanish or diverge on restart:** in-memory cards vs file ledger (`backend/app/main.py:29-37,54-57`). **Mitigation:** use a fresh demo data directory and restart-check persisted cards/ledger before recording.
- **No live path demonstrates trust claims safely:** self-declared skills, flags, host decisions and credential export need clear UI boundaries (`PRD.md:30,38`; `TRD.md:49`). **Mitigation:** show a flagged draft, host correction/confirmation, verify chain, and visibly say hash is not truth/credential is unsigned.
- **Synthetic realism can be challenged:** all outcomes are generated (`PRD.md:41,47`; `ADR.md:45-48`). **Mitigation:** label every screen/output and show generator assumptions plus misses, not just aggregate wins.

## 5. Missing judge-facing requirements

- Define a traceable consent/provenance record for each contribution (who reported it, which attendance source, who reviewed it, when corrected); confirmation is not proof of hours.
- Add a concrete threat/data lifecycle statement: what is stored, where, retention/deletion, who can view/export, and how secrets/cache/ledger files are handled. The local prototype has no authentication and accepts arbitrary `actor` (`backend/app/main.py:161-175`).
- Specify bias evaluation denominators and safeguards for small groups: compare qualified/eligible opportunities and outcomes by district/gender without exposing small-cell data; do not equate parity with fairness.
- Define user-visible abstention, correction, solver infeasibility and manual fallback behavior in English/Hindi; specify keyboard/screen-reader checks for the WCAG target.
- Pin evaluation dataset/version, generator seed, solver version/settings, model/cache identifiers and exact command/output artifact so claims are reproducible across reruns.
- State service limits and failure behavior for larger pools, solver timeouts, offline mode/cache miss, and export failures; current “scales comfortably” is unsupported by a measured limit (`ADR.md:20-23`).
